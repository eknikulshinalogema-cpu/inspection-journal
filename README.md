# Электронный журнал осмотра помещений и оборудования

Приложение для Bitrix24 Vibecode: PHP + SQLite, встраиваемое приложение портала.

## Структура

```
public/index.php   — точка входа, роутер (?route=list|create|journal|admin)
src/                — классы (Database, Auth, JournalRepository, SettingsRepository, SummaryService, Numbering)
views/              — HTML-шаблоны
config/default_rows.php — 33 строки для автозаполнения нового журнала (см. примечание ниже)
data/               — SQLite-файл создаётся сюда автоматически при первом запросе
.vibecode           — манифест деплоя
composer.json       — зависимость bitrix24/bitrix24-php-sdk
```

## Перед деплоем

1. `composer install --no-dev` — подтянет `bitrix24/bitrix24-php-sdk` (в моей песочнице нет доступа
   к Packagist, поэтому я не смог прогнать эту команду и приложить готовый `vendor/`; это должно
   выполниться автоматически на сервере Vibecode согласно `.vibecode`, либо вручную).
2. Убедитесь, что папка `data/` доступна на запись — туда создаётся `journal.sqlite`
   при первом обращении (таблицы создаются автоматически, отдельного install-скрипта не нужно).
3. Приложению нужны права на методы Б24: `user.current`, `user.get`, `department.get`.

## Как работает авторизация Б24

`src/Auth.php` читает токен доступа/refresh/домен портала из параметров запроса
(`AUTH_ID`, `REFRESH_ID`, `DOMAIN` — стандартные для встраиваемых приложений Б24) или из
сессии/переменных окружения, и строит клиент через `bitrix24/bitrix24-php-sdk`.
`Auth::isAdmin()` определяет права администратора по `user.current` (`ADMIN=Y`) — от этого
зависит доступ к `/admin`.

## Что уже проверено (в этой сессии, без сети)

- Синтаксис всех PHP-файлов (`php -l`) — без ошибок.
- Полный прогон бизнес-логики на реальном SQLite-файле (без обращения к Б24 SDK):
  создание журнала → автозаполнение строк → нумерация (1, 1.1, 2, 2.1 …) →
  валидация "Завершить" (блокирует при пустых полях) → генерация выжимки
  (✅/⚠ нарушения) → топ-3 слов по комментариям с исключением стоп-слов.
  Все сценарии отработали корректно.
- Что НЕ проверено: реальные вызовы Bitrix24 REST API (`user.current`, `user.get`,

## Примечание по расхождению в ТЗ

В тексте задачи сказано "все 34 строки", но сам массив `$defaultRows` в ТЗ содержит
33 элемента (sort 10…330 с шагом 10). Я перенёс ровно те 33 строки, что были в массиве —
если нужна 34-я, добавьте её через `/admin` (кнопка "Добавить новую строку") после деплоя.

## Известные ограничения / что стоит уточнить

- `Auth::isAdmin()` определяет админа по полю `ADMIN` в ответе `user.current` — это
  стандартное поведение SDK, но стоит проверить на вашем портале, что оно возвращается.
- Права доступа групп (`/admin`, раздел "Права доступа групп") сохраняются в таблицу
  `access_groups`, но сейчас **не применяются** как реальное ограничение доступа к
  `/journal` или `/admin` — в ТЗ описана только возможность их *назначить*, поэтому я не
  стал додумывать, как именно это должно ограничивать доступ (по авторизованному
  пользователю нужен список его групп через `user.get(ID=...)`+`UF_DEPARTMENT`, это можно
  добавить, если нужно реальное применение прав).
